CKKS 동형암호화 적용 방식 및 수학적 구조 정리
================================================

1. 이 프로젝트에서 암호화를 사용한 목적
------------------------------------

현재 프로젝트는 업로드된 표 데이터에 대해 다음 세 가지 회귀 분석 결과를 비교한다.

1) Classical regression
2) Quantum HHL regression
3) HE + HHL regression

여기서 HE + HHL 방식은 TenSEAL의 CKKS 동형암호화를 사용해 입력 데이터 일부를
암호화한 뒤, 암호문 상태에서 회귀에 필요한 집계 연산을 수행한다. 이후 집계 결과를
복호화하여 HHL 기반 선형 시스템 풀이에 사용한다.

프론트엔드에 표시되는 "CKKS Encrypted Data" 값은 원본 숫자가 아니라 CKKS 암호문을
직렬화한 bytes를 base64로 인코딩한 미리보기이다. 즉, 사람이 읽을 수 있는 실제
데이터 값이 아니라 "이 데이터가 CKKS ciphertext로 변환되었다"는 것을 확인하기 위한
암호문 표현이다.


2. 코드상 구현 위치
------------------

주요 구현 파일:

- backend/he_hhl_solver.py
- frontend/app.js
- frontend/index.css

백엔드의 핵심 함수는 run_analysis(...)이다. 이 함수 안에서 x, y 데이터를 정리하고,
TenSEAL CKKS context를 생성한 뒤, z와 y 벡터를 CKKS 벡터로 암호화한다.


3. 사용한 CKKS 설정
------------------

backend/he_hhl_solver.py의 setup_tenseal_context()에서 다음 설정을 사용한다.

- scheme: CKKS
- poly_modulus_degree: 8192
- coeff_mod_bit_sizes: [60, 40, 40, 60]
- global_scale: 2^40
- galois_keys: generated

의미:

- poly_modulus_degree = 8192
  CKKS가 계산을 수행하는 다항식 환의 차수와 관련된다. 일반적으로 값이 클수록
  더 많은 slot과 더 큰 보안/연산 여유를 제공하지만 계산 비용도 증가한다.

- coeff_mod_bit_sizes = [60, 40, 40, 60]
  CKKS의 modulus chain을 구성한다. 곱셈을 수행할 때 scale이 커지므로 rescale을 통해
  modulus chain을 한 단계씩 소비한다.

- global_scale = 2^40
  실수 또는 복소수 값을 정수 다항식으로 근사 인코딩하기 위해 사용하는 스케일이다.
  CKKS는 정확한 정수 암호가 아니라 근사 실수 연산을 제공하므로 scale 선택이 중요하다.

- Galois keys
  CKKS slot 회전 같은 연산에 필요한 키이다. TenSEAL의 dot 연산은 내부적으로 slot 회전을
  활용할 수 있으므로 galois key를 생성한다.


4. 데이터 전처리와 회귀 문제 구성
--------------------------------

입력 데이터에서 유효한 숫자만 남긴다.

    mask = isfinite(x_values) AND isfinite(y_values)
    x = x_values[mask]
    y = y_values[mask]
    n = len(x)

x 값은 표준화한다.

    x_center = mean(x)
    x_scale  = std(x)
    z_i = (x_i - x_center) / x_scale

표준화된 회귀 모델은 다음과 같다.

    y_i ~= beta_0 + beta_1 z_i

디자인 행렬 X_z는 다음과 같다.

    X_z =
    [1  z_1]
    [1  z_2]
    ...
    [1  z_n]

릿지 항 lambda를 아주 작게 추가하여 선형 시스템을 안정화한다.

    A_z = X_z^T X_z + lambda I
    b_z = X_z^T y

즉,

    A_z =
    [ n          sum(z_i)      ]
    [ sum(z_i)   sum(z_i^2)    ] + lambda I

    b_z =
    [ sum(y_i)       ]
    [ sum(z_i y_i)   ]

해는 다음 선형 시스템으로 얻는다.

    A_z beta_z = b_z

표준화 좌표계에서 구한 beta_z를 원래 x 좌표계의 intercept, slope로 변환한다.

    slope_original = beta_1 / x_scale
    intercept_original = beta_0 - beta_1 * x_center / x_scale


5. HE + HHL에서 암호화한 값
--------------------------

HE + HHL 단계에서는 다음 두 벡터를 CKKS로 암호화한다.

    enc_z = CKKS.encrypt([z_1, z_2, ..., z_n])
    enc_y = CKKS.encrypt([y_1, y_2, ..., y_n])

여기서 enc_z와 enc_y는 TenSEAL의 ckks_vector 객체이다. 이 객체는 원본 실수 배열을
CKKS plaintext로 인코딩한 뒤 공개키 방식으로 암호화한 ciphertext를 담고 있다.

프론트엔드에 표시하기 위해 enc_z와 enc_y를 serialize()로 bytes로 바꾸고, 그 bytes를
base64 문자열로 변환한다.

    serialized = encrypted_vector.serialize()
    base64_preview = base64(serialized)[0:120]
    sha256 = SHA256(serialized)

표시되는 정보:

- scheme: CKKS
- value_count: 암호화 전 벡터에 들어간 값 개수
- ciphertext_bytes: 직렬화된 암호문 bytes 크기
- sha256: 암호문 bytes의 해시
- base64_preview: 암호문 bytes를 base64로 바꾼 앞부분

주의할 점:

base64_preview는 원본 값을 암호화한 결과의 일부 표현일 뿐이며, 이 문자열만 보고 원본
숫자를 알 수 없다. 또한 전체 암호문도 비밀키 없이는 복호화할 수 없다.


6. 암호문 상태에서 수행한 동형 연산
----------------------------------

회귀 계산에 필요한 값은 전체 데이터 자체가 아니라 다음 집계값들이다.

    sum(y_i)
    sum(y_i^2)
    sum(z_i)
    sum(z_i^2)
    sum(z_i y_i)

이 프로젝트에서는 CKKS 암호문 상태에서 다음 연산을 수행한다.

    enc_sum_y    = enc_y.dot([1, 1, ..., 1])
    enc_sum_y_sq = (enc_y * enc_y).dot([1, 1, ..., 1])

    enc_sum_z    = enc_z.dot([1, 1, ..., 1])
    enc_sum_z_sq = (enc_z * enc_z).dot([1, 1, ..., 1])
    enc_sum_zy   = (enc_z * enc_y).dot([1, 1, ..., 1])

수학적으로는 다음과 같다.

    Enc(y) homomorphic-dot 1 = Enc(sum(y_i))
    Enc(y) * Enc(y) = Enc(y_i^2) for each slot
    Enc(z) * Enc(y) = Enc(z_i y_i) for each slot

CKKS는 SIMD packing을 지원하므로 여러 값을 하나의 ciphertext slot들에 담고,
slot-wise 연산을 수행할 수 있다.


7. CKKS의 수학적 구조
--------------------

CKKS는 근사 실수/복소수 연산을 위한 격자 기반 동형암호이다. BFV/BGV처럼 정확한 정수
연산을 목표로 하기보다, 머신러닝이나 통계 계산처럼 약간의 근사 오차를 허용하는
실수 연산에 적합하다.

7.1 다항식 환

CKKS는 보통 다음과 같은 다항식 환 위에서 동작한다.

    R_Q = Z_Q[X] / (X^N + 1)

여기서:

- N은 poly_modulus_degree이다. 이 프로젝트에서는 N = 8192이다.
- Q는 ciphertext modulus이다.
- Z_Q는 modulo Q 정수 집합이다.
- X^N + 1로 나눈 나머지 다항식 공간에서 연산한다.

즉, ciphertext는 단순한 숫자 하나가 아니라 이 환 위의 다항식 쌍 또는 다항식 묶음으로
볼 수 있다.

7.2 인코딩

원본 실수 벡터는 바로 암호화되지 않는다. 먼저 CKKS encoding을 통해 다항식 plaintext로
변환된다.

    m = [m_1, m_2, ..., m_k]
    plaintext = Encode(m, Delta)

여기서 Delta는 scale이다. 이 프로젝트에서는 Delta = 2^40이다.

개념적으로는 다음과 같은 일이 일어난다.

1) 실수/복소수 벡터를 CKKS slot에 배치한다.
2) canonical embedding의 역변환을 사용해 다항식 계수 형태로 바꾼다.
3) scale Delta를 곱해 근사 정수 다항식으로 만든다.
4) 반올림을 거쳐 plaintext polynomial을 만든다.

따라서 CKKS에서는 복호화 후에도 완전히 같은 값이 아니라 원본에 가까운 근사값이 나온다.

7.3 암호화

CKKS의 보안성은 Ring-LWE 문제에 기반한다. 간단히 말하면, 비밀키 s와 무작위성, 작은
오차 e를 섞어 만든 다항식 관계에서 s를 알아내기 어렵다는 가정에 기반한다.

일반적인 ciphertext는 다음과 같은 형태의 다항식 쌍으로 생각할 수 있다.

    ct = (c_0, c_1)

복호화는 대략 다음 구조를 가진다.

    c_0 + c_1 * s ~= plaintext

여기서 ~=는 noise와 근사 오차가 포함된다는 뜻이다.

7.4 덧셈

두 암호문이 같은 scale과 modulus level에 있으면 덧셈은 component-wise로 수행된다.

    Enc(a) + Enc(b) = Enc(a + b)

프로젝트의 sum 연산은 내부적으로 slot 회전과 덧셈을 이용해 전체 slot 값을 합치는
방식으로 구현될 수 있다.

7.5 곱셈

곱셈은 다음 성질을 사용한다.

    Enc(a) * Enc(b) = Enc(a * b)

단, CKKS 곱셈 후에는 scale이 커진다.

    scale: Delta * Delta = Delta^2

그래서 rescale 과정을 거쳐 scale을 다시 적절한 크기로 낮추고 modulus chain을 한 단계
소비한다. 곱셈을 많이 할수록 남은 modulus level이 줄어든다.

이 프로젝트의 HE 연산은 주로 제곱과 원소별 곱 이후 합산 정도이므로 비교적 얕은
연산 깊이를 사용한다.


8. HE 집계 결과를 HHL에 연결하는 방식
------------------------------------

동형 연산으로 얻은 집계 암호문은 다음과 같이 복호화한다.

    dec_sum_y    = Decrypt(enc_sum_y)
    dec_sum_y_sq = Decrypt(enc_sum_y_sq)
    dec_sum_z    = Decrypt(enc_sum_z)
    dec_sum_z_sq = Decrypt(enc_sum_z_sq)
    dec_sum_zy   = Decrypt(enc_sum_zy)

그 다음 복호화된 집계값으로 회귀 선형 시스템을 만든다.

    A_he =
    [ n          dec_sum_z      ]
    [ dec_sum_z  dec_sum_z_sq   ] + lambda I

    rhs_he =
    [ dec_sum_y    ]
    [ dec_sum_zy   ]

그리고 HHL solver에 전달한다.

    beta_he_hhl_z = HHL(A_he, rhs_he)

마지막으로 표준화 좌표계의 계수를 원래 좌표계로 변환한다.

    intercept_he_hhl, slope_he_hhl =
        convert_standardized_coefficients(beta_he_hhl_z, x_center, x_scale)


9. 현재 구현의 보안/구조상 특징
------------------------------

현재 구현은 "암호화된 상태에서 필요한 집계 연산을 수행한다"는 흐름을 보여주기 위한
교육용/데모용 구조에 가깝다.

중요한 특징은 다음과 같다.

1) 원본 z, y 벡터는 CKKS ciphertext로 변환된다.

2) sum, square, product 같은 회귀 집계 연산은 암호문 상태에서 수행된다.

3) HHL에 넣기 전 집계값은 서버 내부에서 복호화된다.
   즉, 현재 구조는 end-to-end encrypted inference라기보다는 "암호화된 데이터로
   일부 통계 집계를 계산한 뒤 복호화하여 양자/HHL 단계와 연결하는 hybrid pipeline"이다.

4) 프론트엔드에는 복호화된 원본 데이터가 아니라 직렬화된 ciphertext preview가 표시된다.

5) CKKS는 근사 연산이므로 HE + HHL 결과는 classical 결과와 아주 미세하게 차이날 수 있다.
   이 차이는 CKKS encoding/scale/rescale/noise와 HHL 근사 오차에서 발생할 수 있다.


10. 전체 파이프라인 요약
-----------------------

입력:

    x_values, y_values

전처리:

    z_i = (x_i - mean(x)) / std(x)

암호화:

    enc_z = CKKS.encrypt(z)
    enc_y = CKKS.encrypt(y)

동형 집계:

    enc_sum_y    = Enc(sum(y_i))
    enc_sum_y_sq = Enc(sum(y_i^2))
    enc_sum_z    = Enc(sum(z_i))
    enc_sum_z_sq = Enc(sum(z_i^2))
    enc_sum_zy   = Enc(sum(z_i y_i))

복호화:

    sum_y, sum_y_sq, sum_z, sum_z_sq, sum_zy

선형 시스템:

    A_he beta = rhs_he

HHL 풀이:

    beta = HHL(A_he, rhs_he)

좌표 변환:

    beta_z -> original intercept, slope

프론트엔드 표시:

    regression metrics
    CKKS ciphertext base64 preview
    ciphertext bytes
    sha256 hash


11. 프론트엔드에 표시되는 암호문 값의 해석
---------------------------------------

예시로 화면에 다음과 같은 정보가 표시된다.

    target y values
    CKKS | 30 value(s) | 334147 bytes | sha256 abc123...
    Ci4K...base64...

이는 다음을 의미한다.

- target y values:
  y 데이터 벡터를 암호화한 ciphertext이다.

- 30 value(s):
  암호화 전에 벡터에 들어 있던 값의 개수이다.

- 334147 bytes:
  TenSEAL이 직렬화한 ciphertext의 크기이다.

- sha256:
  ciphertext bytes의 해시이다. 암호문이 달라지면 해시도 달라진다.

- base64 preview:
  ciphertext bytes를 사람이 볼 수 있는 문자열 형태로 바꾼 앞부분이다.

동일한 원본을 암호화하더라도 CKKS 암호화는 무작위성을 포함하므로 매번 ciphertext와
sha256이 달라질 수 있다. 이것은 정상적인 암호화 동작이다.
