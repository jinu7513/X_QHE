QHE amplitude encoding handoff 로직 및 수식 정리
================================================

1. 이 문서의 목적
----------------

현재 프로젝트는 기본적으로 CKKS 동형암호와 HHL-style 양자 선형시스템 풀이를 결합한
보안 데이터 분석 앱이다. 여기에 추가로, 수치형 스프레드시트 데이터 전체를 양자 상태로
인코딩하고 Quantum One-Time Pad(QOTP) 기반의 제한적 양자동형암호화(QHE) 과정을
시뮬레이션한 뒤, 복호화된 데이터를 기존 HHL 회귀분석으로 넘기는 handoff demo를
구현했다.

이 문서는 다음 내용을 설명한다.

- 30개 수치 데이터를 5-qubit amplitude encoding으로 표현하는 방식
- QOTP 기반 양자 암호화 수식
- Clifford gate에 대한 key update 규칙
- 복호화 후 HHL로 handoff하는 흐름
- fidelity와 reconstruction error를 확인하는 이유
- 이 구현이 가능한 범위와 한계

코드상 주요 구현 위치:

- streamlit_app.py
  - prepare_amplitude_payload(...)
  - apply_qotp(...)
  - update_h_key(...)
  - update_cx_key(...)
  - run_qhe_hhl_handoff(...)
  - render_qhe_hhl_handoff(...)


2. 전체 파이프라인
------------------

현재 QHE handoff demo의 전체 흐름은 다음과 같다.

1) 스프레드시트에서 하나의 target y 컬럼을 선택한다.

2) 유효한 x, y 쌍만 남긴다.

3) y 전체 벡터를 mean-centering한다.

    y_centered_i = y_i - mean(y)

4) 벡터 길이를 2의 거듭제곱으로 맞추기 위해 zero padding한다.

    현재 샘플 데이터는 30개 행이므로 32차원으로 padding한다.

    2^5 = 32

    따라서 5 qubit으로 30개 데이터를 amplitude encoding할 수 있다.

5) L2 norm으로 정규화하여 양자 상태의 amplitude 조건을 만족시킨다.

    ||v||_2 = sqrt(sum_i v_i^2)

    alpha_i = v_i / ||v||_2

6) 정규화된 벡터를 5-qubit 양자 상태로 만든다.

    |psi> = sum_{i=0}^{31} alpha_i |i>

7) Quantum One-Time Pad로 |psi>를 암호화한다.

8) 암호화된 상태에 Clifford gate 회로를 적용한다.

9) Clifford gate에 따른 QOTP key update를 수행한다.

10) 업데이트된 key로 복호화한다.

11) 복호화된 양자 상태가 원래 상태와 일치하는지 fidelity를 확인한다.

12) 복호화된 amplitude를 다시 classical y 값으로 복원한다.

13) 복원된 y 값을 기존 HHL 회귀분석 파이프라인에 넣는다.


3. Amplitude encoding 수식
--------------------------

선택된 target column을 다음과 같이 둔다.

    y = [y_0, y_1, ..., y_{n-1}]

샘플 데이터에서는 n = 30이다.

먼저 평균을 제거한다.

    mu = (1/n) sum_{i=0}^{n-1} y_i

    v_i = y_i - mu

평균을 제거하는 이유는 데이터의 전체 offset보다 변화량을 amplitude에 담기 위함이다.
가격 데이터처럼 절대값이 큰 데이터는 그대로 정규화하면 변화 패턴보다 큰 평균값이
amplitude를 지배할 수 있다. mean-centering을 하면 데이터의 변동 구조가 더 잘 드러난다.

다음으로 길이를 2의 거듭제곱으로 맞춘다.

    N = 2^m >= n

현재 n = 30이므로,

    m = ceil(log2(30)) = 5
    N = 32

따라서 2개의 0을 뒤에 붙인다.

    v_pad = [v_0, v_1, ..., v_29, 0, 0]

양자 상태는 amplitude 제곱합이 1이어야 하므로 L2 정규화를 수행한다.

    L = ||v_pad||_2 = sqrt(sum_{i=0}^{N-1} v_pad_i^2)

    alpha_i = v_pad_i / L

그 결과 다음 상태를 만든다.

    |psi> = sum_{i=0}^{N-1} alpha_i |i>

N = 32이므로 basis state는 다음과 같다.

    |00000>, |00001>, ..., |11111>

즉 30개 데이터가 5-qubit statevector의 amplitude로 들어간다.

코드에서는 Qiskit Statevector를 사용하여 이 상태를 직접 구성한다.


4. Quantum One-Time Pad(QOTP) 암호화
-----------------------------------

QOTP는 양자 상태에 대한 one-time pad이다. 각 qubit마다 두 개의 secret bit를 사용한다.

    a_j in {0, 1}
    b_j in {0, 1}

여기서 j는 qubit index이다. 5 qubit이면 다음과 같은 key를 갖는다.

    a = [a_0, a_1, a_2, a_3, a_4]
    b = [b_0, b_1, b_2, b_3, b_4]

각 qubit에는 Pauli X와 Z를 적용한다.

    Enc(|psi>) = (tensor_j X_j^{a_j} Z_j^{b_j}) |psi>

코드에서는 global phase 차이를 크게 신경쓰지 않는 fidelity 비교를 사용하므로,
실제 적용 순서는 다음과 같이 구현되어 있다.

    Z^{b_j} 적용 후 X^{a_j} 적용

QOTP의 의미는 다음과 같다.

- a_j = 1이면 j번째 qubit에 X gate를 적용한다.
- b_j = 1이면 j번째 qubit에 Z gate를 적용한다.
- key를 모르는 서버는 암호화된 양자 상태만 받는다.
- 이 상태는 원래 |psi>에 대한 정보를 숨긴다.


5. Clifford gate와 key update
-----------------------------

QHE의 핵심은 서버가 암호화된 상태 위에서 연산을 수행하고, 사용자는 key를 update하여
복호화할 수 있다는 점이다.

현재 demo에서는 H, CNOT 같은 Clifford gate만 사용한다. 이유는 Clifford gate가 Pauli
operator를 다시 Pauli operator로 보존하기 때문에 QOTP key update가 간단하기 때문이다.

즉 어떤 Clifford gate C에 대해 다음 구조가 성립한다.

    C X^a Z^b |psi>
      = X^{a'} Z^{b'} C |psi>

여기서 a', b'는 gate C에 따라 update된 key이다.

현재 구현한 key update 규칙은 다음과 같다.

H gate:

    H X H = Z
    H Z H = X

따라서 H가 qubit j에 적용되면 key는 서로 교환된다.

    (a_j, b_j) -> (b_j, a_j)

S gate를 쓸 경우 일반적인 규칙은 다음과 같다.

    S X S^dagger = XZ
    S Z S^dagger = Z

따라서

    (a_j, b_j) -> (a_j, a_j xor b_j)

현재 코드에는 update_s_key는 구현하지 않았고, H와 CNOT 기반 identity-preserving
Clifford 회로만 사용한다.

CNOT gate:

control = c, target = t일 때 Pauli propagation은 다음과 같다.

    X_c -> X_c X_t
    X_t -> X_t
    Z_c -> Z_c
    Z_t -> Z_c Z_t

따라서 QOTP key update는 다음과 같다.

    a_t <- a_t xor a_c
    b_c <- b_c xor b_t

이 규칙이 streamlit_app.py의 update_cx_key(...)에 구현되어 있다.


6. 왜 identity-preserving Clifford 회로를 사용했는가
---------------------------------------------------

현재 demo에서는 다음과 같은 Clifford gate sequence를 사용한다.

    H(q0)
    CX(q0, q1)
    CX(q0, q1)
    H(q0)

여기서 H는 두 번 적용되면 identity이다.

    H H = I

CNOT도 같은 control-target에 두 번 적용하면 identity이다.

    CNOT CNOT = I

따라서 전체 평문 효과는 identity이다.

    U = H CX CX H = I

이렇게 구성한 이유는 QHE handoff 후에도 원래 데이터 벡터가 보존되어야 기존 HHL 회귀분석
결과와 자연스럽게 비교할 수 있기 때문이다.

하지만 암호화된 상태에서는 실제로 다음 과정이 일어난다.

    |psi>
      -> QOTP encryption
      -> Clifford evaluation
      -> key update
      -> QOTP decryption
      -> |psi>

즉 계산 결과는 원래 상태로 돌아오지만, 중간에는 암호화된 양자 상태 위에서 gate가
적용되고 key update가 수행된다. 이 때문에 QHE 원리, 즉 "암호화된 상태에서 연산하고
복호화 후 올바른 결과를 얻는 구조"를 확인할 수 있다.


7. 복호화와 classical 데이터 복원
---------------------------------

복호화는 업데이트된 key a', b'를 사용한다.

암호화가

    X^a Z^b |psi>

형태라면 복호화는 반대 Pauli correction을 적용하는 것이다. Pauli gate는 자기 자신의
역원이므로,

    X X = I
    Z Z = I

업데이트된 key를 사용해 다시 X와 Z를 적용하면 원래 상태로 돌아온다.

복호화된 상태를 다음과 같이 둔다.

    |psi_dec> = sum_i beta_i |i>

원래 scaling 과정을 되돌리면 classical y 값을 복원할 수 있다.

    recovered_centered_i = beta_i * L

    recovered_y_i = recovered_centered_i + mu

여기서 i는 원래 데이터 길이 n까지만 사용한다. padding된 마지막 2개 amplitude는 버린다.


8. HHL handoff
--------------

복원된 y 값은 기존 회귀분석 함수 run_analysis(x, recovered_y)에 들어간다.

기존 HHL 회귀분석 흐름은 다음과 같다.

1) x를 표준화한다.

    z_i = (x_i - mean(x)) / std(x)

2) 디자인 행렬을 만든다.

    X_z =
    [1  z_1]
    [1  z_2]
    ...
    [1  z_n]

3) 정규방정식을 구성한다.

    A beta = b

    A = X_z^T X_z + ridge I
    b = X_z^T y

구체적으로는,

    A =
    [ n        sum(z)   ]
    [ sum(z)   sum(z^2) ] + ridge I

    b =
    [ sum(y)   ]
    [ sum(z*y) ]

4) Qiskit 기반 HHL-style solver로 2x2 선형시스템을 푼다.

    beta = A^{-1} b

5) 표준화 좌표계의 beta를 원래 x 좌표계의 intercept, slope로 변환한다.

따라서 QHE handoff demo의 의미는 다음과 같다.

    전체 y 데이터
      -> amplitude encoding
      -> QOTP 기반 제한적 QHE
      -> 복호화 및 y 복원
      -> HHL 회귀분석


9. 왜 fidelity를 확인하는가
---------------------------

QHE handoff에서 가장 중요한 질문은 다음이다.

    암호화된 양자 상태 위에서 gate를 적용하고 key update를 수행한 뒤,
    복호화했을 때 원래 의도한 양자 상태가 제대로 복원되는가?

이를 확인하기 위해 fidelity를 사용한다.

순수 상태 |psi>와 |phi>의 fidelity는 다음과 같다.

    F(|psi>, |phi>) = |<psi|phi>|^2

여기서

    |psi> = 원래 amplitude encoded state
    |phi> = QOTP 암호화 -> Clifford evaluation -> 복호화 후 state

이다.

fidelity의 의미:

- F = 1이면 두 양자 상태가 완전히 같다.
- F = 0이면 서로 직교한다.
- 1에 가까울수록 QHE 과정이 원래 의도한 상태를 잘 보존했다는 뜻이다.

이 프로젝트의 샘플 데이터 검증 결과는 다음과 같았다.

    fidelity = 0.9999999999999993

이는 수치 오차 수준을 제외하면 복호화된 상태가 원래 amplitude encoded state와 같다는
뜻이다.

fidelity를 확인하는 이유는 classical 데이터 값만 비교하면 양자 상태의 global phase나
statevector 수준의 차이를 충분히 설명하기 어렵기 때문이다. QHE는 양자 상태 자체를
암호화하고 연산하는 구조이므로, statevector 수준에서 올바른 상태가 복원되었는지
확인하는 fidelity가 적절한 지표이다.


10. 왜 reconstruction error도 확인하는가
----------------------------------------

fidelity는 양자 상태의 일치도를 확인하는 지표이다. 하지만 최종 앱 사용자는 classical
스프레드시트 데이터를 다룬다. 따라서 양자 상태가 잘 복원되었더라도, 그것을 다시 y 값으로
되돌렸을 때 실제 데이터가 얼마나 잘 복원되는지도 확인해야 한다.

이를 위해 reconstruction error를 계산한다.

    error = max_i |recovered_y_i - y_i|

샘플 데이터 검증 결과는 다음과 같았다.

    reconstruction error = 0.0

이는 amplitude encoding, QOTP 암호화, Clifford evaluation, 복호화, classical 복원 과정을
거친 뒤에도 y 데이터가 그대로 복원되었음을 의미한다.

즉 두 지표는 서로 다른 관점을 확인한다.

- fidelity: 양자 상태 수준에서 복호화가 올바른가?
- reconstruction error: classical 데이터 수준에서 값이 보존되었는가?


11. 현재 구현의 의의
--------------------

현재 구현은 전체 target y 데이터를 실제로 5-qubit amplitude state로 encoding한다.
이는 단순히 "이론적으로 가능하다"고 말하는 것이 아니라, 선택된 30개 데이터가 32차원
양자 상태로 들어가는 과정을 코드로 수행한다.

또한 QOTP 기반으로 다음을 확인한다.

- secret key a, b 생성
- Pauli X/Z 기반 암호화
- Clifford gate evaluation
- Clifford gate에 따른 key update
- 복호화
- fidelity 확인
- classical 데이터 복원
- 복원된 데이터의 HHL handoff

따라서 이 demo는 "수치형 스프레드시트 데이터를 양자 상태로 만들고, 제한적 QHE 원리를
적용한 뒤 기존 HHL 분석 파이프라인과 연결한 시도"라고 설명할 수 있다.


12. 현재 구현의 한계
--------------------

중요한 점은, 이 구현이 HHL 전체를 QHE 내부에서 실행한 것은 아니라는 점이다.

현재 구현:

    amplitude encoding
      -> QOTP 기반 제한적 QHE
      -> 복호화
      -> HHL handoff

아직 구현하지 않은 것:

    amplitude encoding
      -> QOTP/QHE 암호화
      -> 암호화된 상태에서 HHL 전체 실행
      -> 복호화

HHL 전체를 QHE로 감싸기 어려운 이유는 HHL 회로가 단순 Clifford 회로가 아니기 때문이다.
HHL에는 다음 요소가 포함된다.

- phase estimation
- controlled rotation
- eigenvalue inversion
- post-selection 또는 measurement

특히 controlled rotation이나 T gate 계열 non-Clifford 연산은 QOTP key update만으로
간단히 처리되지 않는다. 이를 QHE로 처리하려면 magic state, gate teleportation,
classical FHE와의 결합, interactive key update 등 훨씬 복잡한 프로토콜이 필요하다.

따라서 현재 구현은 다음과 같이 표현하는 것이 가장 정확하다.

    "본 프로젝트는 전체 수치 데이터를 amplitude encoding하여 양자 상태로 만들고,
    QOTP 기반 제한적 QHE 과정을 시뮬레이션한 뒤, 복호화된 데이터를 HHL 회귀분석으로
    넘기는 handoff demo를 구현했다. HHL 전체를 암호화된 양자 상태 위에서 실행한 것은
    아니며, 이는 non-Clifford 연산과 측정 처리가 필요한 향후 과제로 남겨두었다."


13. 발표용 요약 문장
--------------------

짧게 설명할 때는 다음과 같이 말할 수 있다.

    "샘플 데이터는 30개 행이므로 하나의 수치형 컬럼 전체를 32차원으로 padding하여
    5-qubit amplitude encoding을 수행했다. 이후 Quantum One-Time Pad로 양자 상태를
    암호화하고, Clifford gate에 대해서 key update 규칙을 적용하여 제한적 QHE 과정을
    시뮬레이션했다. 복호화 후 원래 양자 상태와의 fidelity가 거의 1이고, classical 값의
    reconstruction error가 0에 가까운 것을 확인한 뒤, 복원된 데이터를 기존 HHL 회귀분석
    파이프라인으로 넘겼다."

더 엄밀하게 말할 때는 다음과 같이 덧붙이면 된다.

    "다만 HHL 전체를 QHE 내부에서 수행한 것은 아니다. HHL은 non-Clifford rotation과
    measurement가 포함되므로, 이를 완전한 QHE로 처리하려면 더 복잡한 연구 수준의
    프로토콜이 필요하다."
